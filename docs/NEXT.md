# Next comparison

I finished the previously memory-limited pinned Qwen2.5-0.5B pair on an L4 and scored six more base/instruct pairs. The [full results](../results/cross_family/analysis/summary.json) support a narrower conclusion than a universal alignment tax: ECE usually worsens, but accuracy does not always improve. The [old CPU attempt](../results/qwen2_5_0_5b) remains separate historical data.

The next useful check is label and answer-order sensitivity, not another large model. I would keep all seven pinned pairs and the same questions, then cross original/reversed A/B placement with leading-space/bare-letter continuations under both existing prompt protocols. I would fix those conditions and their analysis before scoring, average order-counterbalanced predictions only within each question, and report every condition rather than select the best-looking prompt afterward. This directly tests whether low accuracies or calibration differences depend on the response-label convention.

I would retain bf16 weights, scalar inference, restricted-choice likelihoods, all six metrics and question-paired intervals. The already measured L4 run can size a small pilot, but it does not measure these new conditions. I would reserve up to $3 for the extra cloud pass as a planning allowance, not a measured cost or a request against the completed $2.50 budget. Downloads and model loading should be reused within each loaded checkpoint, so a larger condition matrix need not repeat those costs. No runs of this follow-up are included in the current results.

A separate longer-term question is where calibration changes along OLMo's SFT, DPO and RLVR checkpoint sequence. Comparing those stages would help locate changes in one training trajectory; it would still not isolate a causal RL effect without controlled data, objectives and repeated training seeds.
